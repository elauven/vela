# SSR host example

A cart rendered on the server by Go and hydrated in the browser. Two of its
functions cannot be translated from JavaScript to Go, so the project
supplies Go implementations, called **hosts**:

| JavaScript function | Why it is not translated | Host |
| --- | --- | --- |
| `formatPrice` in `src/format.js` | `Intl.NumberFormat` | `ssrhost/src/format/format_price_host.go` |
| `slugify` in `src/Cart.vela` | regular expressions | `ssrhost/src/cart/slugify_host.go` |

The server calls the hosts for the first render; the browser keeps using the
JavaScript functions after hydration.

## Run it

From the repository root:

```sh
go build -o bin/vela .                 # the compiler
cd examples/ssr-host
../../bin/vela --ssr --project src --out out
go run ./cmd/server                    # http://localhost:8080
```

Open <http://localhost:8080> and <http://localhost:8080/?currency=EUR>, then
press **+1**: the totals are updated by the JavaScript `formatPrice`. In
development builds, hydration compares every server value with the client
value; a host that disagrees with its JavaScript function is reported in the
browser console as a hydration mismatch with its source position and host
name.

## Layout

```
vela.ssr.json            Go module paths of the generated server and the hosts
go.mod                   one Go module for the server, the hosts and out/
src/                     components and JavaScript modules
ssrhost/                 host implementations (yours; the compiler never edits them)
cmd/server/main.go       HTTP server: renders Cart, serves out/client and out/styles
out/                     generated by vela --ssr (client/, server/, styles/)
```

## How a host is bound

1. **Package.** A host lives in the package that mirrors its JavaScript file:
   `src/format.js` → `ssrhost/src/format/`, `src/Cart.vela` →
   `ssrhost/src/cart/`.
2. **Directive.** The Go function carries `//vela:host <jsName>`. The Go name
   is free; only the directive binds.
3. **Signature.** Parameters follow the JavaScript parameters by position,
   with an optional first `context.Context`. The result is `R` or
   `(R, error)`. Allowed types: `string`, `bool`, `float64`, integer types
   (parameters), slices, `map[string]T`, structs, `time.Time`, `any`,
   `vela.Optional[T]`.
4. **Parity.** The host must return what the JavaScript function returns for
   the same arguments; the client keeps the JavaScript function.

A directive whose JavaScript function no longer exists is a build error
(`VELA-SSR-HOST-STALE`).

## Writing a new host

Build without the host: the compiler names the file and the signature.

```
$ vela --ssr --project src --out out
  x  Cart.vela: SSR: VELA-SSR-HOST-MISSING: …
       src/Cart.vela:33:32: [error] VELA-SSR-HOST-MISSING
         formatPrice has no server-native translation: method value.format is not available during server rendering
         fix: implement it in Go:
           ssrhost/src/format/format_price_host.go
             //vela:host formatPrice
             func FormatPrice(ctx context.Context, value float64, currency string) (any, error)
           or run: vela --ssr --ssr-scaffold-hosts
```

`--ssr-scaffold-hosts` creates the missing files with a body that returns
`vela.ErrHostNotImplemented`; it never changes an existing file. Build again
after scaffolding. A stub that is still unimplemented fails the render with
the position of the call, so it cannot ship unnoticed.

## Request data

Hosts that take a `context.Context` receive the context passed to
`RenderCartContext(ctx, w, props, slots)`; `cmd/server` passes the request
context. Put the locale, the user or the time zone there instead of in
props or globals.
